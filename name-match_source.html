Review candidates

Pairs that scored just below the match threshold, so they were not merged. These are the genuinely ambiguous cases — e.g. an added middle name, or a shared surname with partial overlap. Inspect and decide for yourself; lower the threshold (or pick Recall) if you want them grouped. Entries scoring at or above the threshold are phonetic transliteration-type candidates (e.g. Juha/Juho) deliberately left for human judgement.

Method: each name is lowercased, accents are optionally folded (Unicode NFD, e.g. ä→a, ö→o, ü→u, with explicit rules for ß→ss, ø→o, æ→ae), name particles are merged (al, van, de, mc, … so “Al-Sayed” and “Alsayed” agree), and the name is split into tokens; single-letter initials are ignored for scoring. Records are compared regardless of word order using Soft TF-IDF: token similarity is Jaro–Winkler, and each token is weighted by its corpus rarity (IDF), so common names contribute little and distinctive names dominate. Candidate pairs are restricted by automatic blocking (shared exact tokens and shared two-token prefixes), so the tool scales to large files without comparing every pair. Known transliteration variants of the same name are normalised with a small verified lexicon (e.g. Muhammad/Mohammed/Mohamed) so they match exactly. Token pairs that are phonetically equivalent under an Editex-style vowel/consonant-group comparison but not in the lexicon (e.g. Juha/Juho) are never auto-merged; the pair is surfaced at the top of the review list for human judgement. Grouping uses chaining-resistant star clustering: each group forms around a seed and a record joins only if it is similar to that seed, which prevents distinct people from being chained into one large cluster. Score is the strongest similarity linking a row to its group: Certain ≥ 0.95, Likely ≥ 0.88, Review ≥ threshold.
References: Christen, P. (2012). Data Matching. Springer. · Cohen, W. W., Ravikumar, P., & Fienberg, S. E. (2003). A comparison of string distance metrics for name-matching tasks. IIWeb-03, 73–78.
